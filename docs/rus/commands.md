# Команды, план и прогресс

Используйте установленное окружение. [Быстрый старт](quickstart.md) показывает
копирование в Bash/Linux. Пути ниже — заполнители независимой рабочей папки.

```sh
mania --help
mania --version
mania run --config /path/to/work/basic.yaml --dry-run
mania run --config /path/to/work/basic.yaml --dry-run --format json
mania run --config /path/to/work/basic.yaml
mania artifacts validate --root /path/to/work/results-basic
```

Каждая форма также работает как `python -I -B -m mania ...` с настоящим
установленным интерпретатором. `mania run --help` и
`mania artifacts validate --help` показывают доступные аргументы. Экспертных
псевдонимов и команд WANIA в публичном CLI нет.

<a id="dry-run"></a>
## Dry-run — предварительный план

| Опция | Реальное поведение |
| --- | --- |
| `--config PATH` | Обязательный строгий YAML; входы и выходы привязаны к его папке |
| `--dry-run` | Ограниченные проверки без записи и читаемый текст по умолчанию |
| `--dry-run --format text` | Явный выбор того же текстового представления |
| `--dry-run --format json` | Полный JSON `mania.run_plan.v1` в stdout |
| `artifacts validate --root PATH` | Проверка явно указанной существующей папки результата |

`--format json` требует `--dry-run`: при выполнении без него код выхода **2**
возникает до расчёта. Это не настройка формата научных результатов. В CLI нет
выбора метода, кадров, переключателя overwrite или автоматического продолжения;
поддерживаемые настройки задаются YAML. JSON-план можно перенаправить в отдельный
файл вне исходного дерева MANIA. Предупреждения Exploratory для JSON идут в stderr, сохраняя
чистый JSON в stdout.

Текстовый план показывает файлы, запрошенные границы кадров с нуля, эффективные
методы и зависимости, профили, выходную папку и перезапись. `READY` /
`READY WITH WARNINGS` означает успех предварительных проверок конфигурации/плана.
`BLOCKED` поясняет ошибку схемы или входных требований. Границы описывают запрос,
а не наблюдённую доступность: `stop` исключён, шаг `stride` отсчитывается от `start`.
Число кадров без верхней границы или при физическом времени неизвестно до чтения.

Dry-run может читать ограниченные метаданные заголовка/топологии и выбранные
файлы научных источников. Он не декодирует всю траекторию, не считает контакты,
Rg/RMSD/QC, не хеширует огромные траектории, не создаёт результаты, не меняет
координаты и не проверяет научную пригодность PBC. Отсутствующая топология даёт
код 3, а не успешный план.

<a id="progress"></a>
## Выполнение и итоговая сводка

Во время выполнения stderr показывает фактические стадии загрузки/проверки,
завершённые методы, запись артефактов и финализацию. Проценты считают выполненные
зарегистрированные стадии работы, **не прогноз времени, ресурсов или научное
одобрение**. Контактный прогресс растёт только при реальных событиях `frame_done`;
без известного общего числа показываются счётчики без процента кадров. Разные
входные идентичности сохраняют отдельные счётчики даже при одинаковых condition.

В терминале прогресс обновляется на месте; перенаправленные потоки используют
редкие обычные строки без ANSI-цветов. Итоговая stdout-сводка содержит затраченное
время, настоящие статусы методов, наблюдённые исходные кадры при наличии, число
артефактов и выходную папку. Успешная финализация может достичь 100%; ошибки,
отмена и ожидание REVIEW сохраняют частичные доказательства без успешной метки
100%. Прогресс — консольное представление; записи научных результатов определяют
CSV/JSON и provenance. После каждого запуска изучайте [Результаты](outputs.md).

<a id="exit-codes"></a>
## Коды выхода и предупреждения

| Код | Значение |
| --- | --- |
| 0 | Help/version; запрошенная работа завершена с допустимыми объяснёнными пропусками preset; либо завершена техническая валидация |
| 2 | Ошибка аргументов CLI, YAML/схемы/типов или противоречивая конфигурация |
| 3 | Нет входа, MD-runtime, выбранного расширения, обязательного источника либо несовместимость до расчёта |
| 4 | Ошибка выполнения или проверки артефактов; неразрешённый обязательный научный барьер |
| 5 | Запрошенный QC ожидает внешнего решения REVIEW |
| 130 | Отмена |

Общие статусы: `completed`, `completed_with_skips`, `pending_review`, `failed`,
`cancelled`. Каждый метод имеет собственный статус и причину: см.
[справочник статусов](outputs.md#statuses). Ошибка явно запрошенного метода
не становится необязательным успешным пропуском.

`SCIENTIFIC_VALIDATION_NOT_PERFORMED` и `authoritative_release_eligible=false`
сохраняются при любом исходе Exploratory; `PBC_UNVERIFIED` обозначает действительно
непроверенный PBC и при необходимости унаследованную связь с источником. Строгий
запуск не принимает Exploratory-входы как научно авторитетное доказательство.

> **Научное предупреждение.** `artifacts validate` проверяет целостность и
> сообщает сохранённый статус запуска. Честно ошибочный результат может пройти
> проверку целостности с кодом 0. Читайте статус и научную квалификацию: код 0
> не подтверждает биологию, пригодность PBC, квалификацию реальных научных входов или решение о публикации.

Ошибка/отмена сохраняет собственные частичные выходы и доступные записи ошибки.
Ошибка до расчёта может возникнуть ещё до появления папки результата. Повторное
использование папки по умолчанию отвергается; явный overwrite в YAML также
проходит проверки владения и безопасности.
